01 — The Stack

The Hierarchy: How Everything Fits

Foundation Layer
🧠 AI / Machine Learning
The broad field. Teaching computers to learn from data. Everything else is built on this.
Subset of AI
📖 LLM — Large Language Models
AI models trained on massive text. They understand and generate human language. Examples: GPT-4, Claude, Gemini, Llama. The "brain" that powers most modern AI products.
Built on top of LLMs
🤖 AI Agents
An LLM given the ability to take actions — browse the web, run code, read files, call APIs. They can complete multi-step tasks autonomously. An agent = LLM + Tools + Loop.
Uses Agents
🛠️ AI Coding Tools (Cursor, Kiro, Q, etc.)
Developer-facing products. They wrap LLMs/Agents into an IDE or CLI experience so you can build software faster. The tools you use day-to-day.

06 — Quick Reference

Key Terms Decoded

Token A chunk of text (~4 chars). LLMs process tokens, not words. You pay per token in cloud APIs.
Context Window How much text an LLM can "see" at once. Bigger = can read more of your codebase at once.
RAG Retrieval Augmented Generation. Fetch relevant docs, inject into prompt so LLM "knows" your data without retraining.
Fine-tuning Retraining a base LLM on your specific data. Expensive but makes it an expert on your domain.
Prompt The instruction you give the LLM. Prompt engineering = writing better instructions to get better output.
Embedding A number array that represents text meaning. Used for semantic search — "find similar" rather than keyword match.
Function Calling Structured way to let an LLM call your code functions. The foundation of how agents use tools.
MCP Model Context Protocol. Standard protocol for connecting LLMs to external tools/data sources. Like REST but for AI agents.
Inference Running the model to generate output. "Running inference on device" = on-device AI, no cloud call needed.
Hallucination When LLMs confidently generate false information. A core challenge — always verify AI output for critical data.
System Prompt Hidden instructions given to the LLM before the user message. Sets personality, rules, and constraints.
Agentic Describes AI that acts autonomously over multiple steps, using tools, rather than just responding to one message.

07 — The New Workflow

Vibe Coding & Spec-Driven Development

🎵 Vibe Coding
You describe what you want in natural language and let the AI write the code. You "vibe" with the output — iterate conversationally rather than writing every line yourself.
Example
"Build me a Compose screen with a pie chart showing portfolio allocation. Each slice should be tappable."

→ Agent writes the full screen, ViewModel, and chart logic.
📋 Spec-Driven Dev (Kiro's Model)
Write a structured spec first (requirements, data model, acceptance criteria). Then give it to the agent. The agent stays grounded — less hallucination, more predictable output.
Kiro's Spec Files

.kiro/steering/ — rules & conventions
.kiro/hooks/ — auto-triggered agents

08 — Orchestration

Multi-Agent Systems & Frameworks

What is a Multi-Agent System?
Instead of one agent doing everything, you have specialized agents that hand off tasks to each other. An Orchestrator agent plans and delegates; Worker agents execute specific tasks.
Why It Matters
Each agent only sees what it needs (smaller context = cheaper + more accurate). Complex workflows like "analyze portfolio → fetch prices → generate report → send email" become manageable.
🎯 Orchestrator Agent
Plans, delegates, assembles results
↙    ↓    ↘
🔍 Research Agent
fetches prices / news
📊 Analysis Agent
calculates risk metrics
✍️ Writer Agent
generates report text
Key Frameworks
🦜 LangChain
Python/JS framework for chaining LLM calls + tools. The most popular. Think of it as a toolkit for building pipelines that combine prompts, retrievers, and agents.
🕸️ LangGraph
Built on LangChain. Models workflows as a graph (nodes = steps, edges = transitions). Great for complex multi-agent flows with loops and branching logic.
🏔️ Amazon Bedrock Agents
AWS-managed multi-agent orchestration. You define agents + tools via config, AWS handles the orchestration loop. Scales well, integrates with AWS services (S3, Lambda, DynamoDB).
🤝 AutoGen (Microsoft)
Agents that converse with each other. One agent critiques another's output. Used for coding tasks where a "reviewer" agent checks a "coder" agent's work.

09 — The Real Skill

Context Engineering & Rules Files

What is Context Engineering?
Prompt engineering = writing a good message. Context engineering = deliberately managing everything the LLM sees — system prompts, codebase structure, memory, retrieved docs, tool results. This is the senior engineer skill for AI.
Analogy: Giving a new dev your full codebase + architecture docs + coding standards before asking them to write a feature. The quality of their output depends entirely on what you gave them upfront.
The Context Window — What Goes In
System Prompt — rules, persona, coding standards
Codebase Files — relevant source files, interfaces
RAG / Docs — retrieved architecture docs, API specs
Conversation History — prior turns, decisions made
Tool Results — output of previous tool calls
User Message — what you just typed
Rules Files — How Each Tool Injects Context
Cursor
.cursorrules
Plain text file in your repo root. Cursor injects it into every prompt. Put your architecture decisions, naming conventions, and forbidden patterns here.
Kiro
.kiro/steering/*.md
Markdown steering docs. Always-on rules for the agent. "Always use BigDecimal for money", "Use Clean Architecture modules", etc.
Claude Code
CLAUDE.md
Drop a CLAUDE.md at your repo root. Claude Code reads it on every session — project structure, build commands, constraints, preferred patterns.
GitHub Copilot
.github/copilot-instructions.md
Repository-level instructions file. Copilot reads this automatically across all chats in that workspace.
Your action: Create a CLAUDE.md and .kiro/steering/android.md in the Custorix repo with your architecture rules (Clean Architecture modules, BigDecimal constraint, Room as SSOT, etc.). Every AI session will be architecture-aware from the first message.

10 — Trust But Verify

LLM Reliability, Evals & Guardrails

The Problem
🌀 Hallucination — LLM confidently returns wrong data. Critical for a crypto app showing portfolio values.
🎲 Non-determinism — Same prompt → different output each time. Hard to test, hard to trust.
💸 Cost drift — Badly designed prompts burn tokens. Agents in a loop can rack up costs fast.
🔒 Prompt injection — Malicious user input hijacks agent behavior. Relevant if users can type free text.
The Solutions
✅ Evals — Automated tests for LLM output. Run a set of known inputs, score outputs. Like unit tests but for AI features.
🛡️ Guardrails — Input/output validators. Reject responses that don't match expected schema or contain disallowed content.
🌡️ Temperature=0 — Set temp to 0 for structured data tasks. Forces the model to be deterministic and consistent.
📐 Structured Output — Force LLM to respond in JSON schema. Parse + validate it. Never trust free-form text for data.

→
📏 Score Output

OpenAI models hosted on Azure. Enterprise compliance (GDPR, SOC2). Same GPT-4 but your data stays in your Azure tenant.

Gemini + open models via Google Cloud. Integrates deeply with Google services. Required if you want Gemini Nano in production pipelines.
⚡ Groq / Together AI
Run open-source models (Llama, Mistral) at very high speed. Great for low-latency use cases. Cheaper than frontier models for simple tasks.
